# Native Elsewords

Elsewords is maintained inside Elsewhere. Its native chat-menu and Settings entry points open the same character-card workspace; installation or updating of a separate plugin is unnecessary. All functions and preferences of the merged Elsewords plugin at `c634135d` are retained. The previous plugin and its repository are not removed automatically. Disable an installed copy manually to avoid duplicate entries.

## Workflow

Load the open character, choose a member of an open group, or stage a JSON/PNG card. Translate its supported prose with the source/target languages, natural/faithful/close style, tone/name options and additional instructions. Alternatively generate a new CCv3-compatible character from a brief, or complete an explicitly staged card with rewrite instructions. No chat transcript or persona is supplied.

Compare the read-only original with editable output (side by side on desktop, stacked on mobile). Fresh creation has output only. Greetings, lorebook prose/names and supported extension prompts are included, including existing empty fields. Update preview validates all drafts without a model call; Cancel edits returns to the last validated result. Pending/invalid drafts block saves, creation and downloads. Translation preserves the spelling and occurrence count of protected variables. Generation, completion and generated-output editing preserve each distinct existing macro in its staged field at least once, including its exact spelling and spacing; repetition may change when prose is rewritten. Legacy role sentinels are normalized to literal {{char}} / {{user}}, malformed role variables are rejected, and required generated prose must remain meaningful. Summary, full JSON, confirmed saves/creation and exports consume one validated output, with no per-field acceptance choices.

Saving an existing character requires confirmation and identity/content conflict checks. Unrelated metadata and chat data remain intact. Creating a separate character has its own confirmation and retains host import/asset checks. Select or generate a PNG/JPEG/WebP portrait, optionally choose a reference or the loaded portrait, and review the preview. References are sent only upon explicit portrait generation when the selected model metadata confirms reference support on the configured Image API route. Unknown or explicitly unsupported reference capability blocks that operation with a route-specific explanation; no alternate provider or route is selected silently. Replacement of an existing profile image is an unchecked confirmation option. JSON/PNG exports retain reviewed edits and applicable imagery. Desktop exports use the native save dialog, including overwrite confirmation; browser downloads use the existing download flow.

## Settings and privacy

The eight local translation preferences are `sourceMode`, `sourceLanguage`, `target`, `customTarget`, `style`, `instructions`, `tone` and `names`. Model configuration and credentials are reused from Elsewhere. Existing image choices (`aspectRatio`, `resolution`, `quality`, `outputFormat`, `seed`) are reused from OpenRouter image settings. No new key or model catalog is introduced.

Optional legacy import reads the old plugin's generic shared LocalForage key only on user request, displays all eight recognized values and requires confirmation. Valid text and false booleans are retained exactly. Ambiguous/unsupported settings are not guessed, overwritten or deleted. The dedicated native preference envelope is versioned and records migration. Existing native preferences are replaced only through the explicit import confirmation. Source cards, drafts, briefs, image prompts, references, portraits, responses and diagnostics are never persisted in this envelope.

Switching tabs retains drafts; opening native model settings suspends the workspace in memory until reopened. Explicit Close clears sensitive session state. Text cancellation uses the request pipeline AbortSignal; providers may already have incurred costs. Closing discards late results. Image cancellation aborts the local request and discards late results; requests already received by a provider may still incur costs. Diagnostics discard tagged reasoning before display and remain bounded and session-only; the 8,000-character display limit is not evidence of provider output-token truncation. Diagnostics can include character text and should not be shared publicly.

Native card requests skip chat orchestration, tool/plugin providers, streaming and multiple generation, with at most one visible parsing/completion recovery. The additive `isolatedContext` request option prevents configured text serializers from reading active character/persona names, parsing stop macros against them or trimming results against those names. It also suppresses private prompt logging in the two legacy prose serializers. Ordinary chat behavior remains unchanged. This is distinct from social-feed `publicOnly` semantics. Shared token-limit validation remains authoritative when integrated; no model-capability table is duplicated here.

## Formats and provenance

Existing formats remain bare/CCv2/CCv3/SillyTavern JSON and standard PNG `tEXt` `chara` metadata, with a 10 MiB file/image limit. Unsupported custom fields remain unchanged; WebP character-card import, nonstandard PNG card metadata and negative image prompts remain unsupported. Portrait dimensions are additionally bounded before canvas conversion.

Native core/adapter/prompt behavior is adapted from Marie's Elsewords implementation. The inspected source history attributes contributions to Marie-Sarah Beaugrand and mariepop13. Its current package has no declared third-party dependencies and its artifact build concatenates local sources. No external attribution/copied-code notice was found in the inspected current sources; this is not an exhaustive originality or legal certification. Elsewhere's existing LICENSE, NOTICE, upstream attribution and rpack notices remain intact. No license file or policy of the separate Elsewords repository is rewritten.
